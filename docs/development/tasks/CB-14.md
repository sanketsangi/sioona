## Implementation

Historical enqueue accepts up to 10,000 distinct persisted conversation IDs,
returns HTTP 202, and snapshots immutable source/context hashes in pages of 500.
The outbox contains references rather than copied transcripts. Processing runs
outside the request in chunks of 100. Historical jobs have lower priority than
live jobs; yielding a normal chunk does not consume failure retries.

The worker uses the existing standard provider route. No approved provider-batch
adapter is configured, so this card does not submit remote batch jobs. Missing
local results remain incomplete references and resume on the next claim. The
existing stable system prompt precedes conversation data; model, prompt, and
privacy behavior are unchanged.

Lease tokens, runtime-role RLS, configuration/source checks, and the tenant
corpus lock fence publication. Detection publication, evidence reconstruction,
completion progress, and application-cache ledger rows commit atomically.
Completed references are skipped after restart. Ambiguous provider attempts
remain pending with unknown usage rather than being silently refunded.
Cancellation and terminal failures preserve remaining IDs for recovery.

Classification cache primary key is exactly
`(tenant_id, content_sha256, prompt_version, model_id, route_version, taxonomy_hash)`.
The content digest includes ordered source roles/text and customer/channel
context, excluding conversation/message IDs so reuse rebuilds evidence for the
current source. Prompt identity incorporates prompt and privacy-port checksums;
taxonomy identity includes base rules and tenant overrides. Entries expire after
seven days. Lookup reparses and regrounds classifications, treating malformed,
unsafe, expired, or ungrounded entries as misses. Both new tables have forced RLS.

Concurrent writes retain the first result for an unexpired key. An atomic upsert
replaces expired entries, so competing calls cannot change a live cached result.
Primary and fallback models use separate keys and separate metered attempts.

Application cache reuse writes a worker-owned `cache_hit=true` inference row with
explicit zero tokens, zero reconciled cost, zero latency, and no provider request
ID or budget reservation. A database constraint rejects incomplete/nonzero hit
rows; clients cannot submit hit rows. Usage APIs expose `cache_hits` separately.
Provider prefix-cache savings remain actual reported `cached_input_tokens`;
application hits never invent saved provider tokens or costs.
