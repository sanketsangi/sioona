# CB-04 — Runtime-role row level security

Status: implemented and proved on disposable Postgres. Not hosted. Not a CB-10 go.
Date: 2026-10-12. Decision: D8, adopt rather than defer.

## What landed

Migration `024_tenant_rls` creates `sioona_runtime` as `NOLOGIN`, `NOSUPERUSER`, and `NOBYPASSRLS`. It enables and forces row level security, one table at a time, on `messages`, `conversations`, `signal_predictions`, `signal_feedback`, `supervised_action_decisions`, `detection_runs`, `inference_attempts`, and `signal_evidence`. The policy is `tenant_id = current_setting('app.tenant_id', true)` for both reads and writes. Missing context matches nothing.

API requests bind that setting after the tenant is known and before tenant queries. The setting is transaction-local, and request teardown clears the context variable. Alembic uses `MIGRATION_DATABASE_URL` when it is set, otherwise `DATABASE_URL`. The runtime role is not given a password in this revision.

Downgrade drops each policy and disables RLS. It keeps the role so an operator password would survive a policy rollback.

## Local evidence

Throwaway Postgres 17, database name `sioona_migration_test` only. `tests/test_postgres_migrations.py` passed, including the new runtime-role test and the existing budget and evidence upgrades. Backend tests other than that file: 251 passed. The migration role for the fixture was a superuser, which is what Render's database owner is. The assertions ran as `sioona_runtime`.

No hosted database was migrated. No staging resource was created.

## Operator switch, still required

1. Apply head on the isolated staging database as the owner. Do this before any runtime-role switch, and do not do it from an agent session.
2. Keep `sioona_runtime` `NOLOGIN` during the CB-03 shadow window. The owner URL bypasses these policies, so that window does not prove RLS.
3. When enforcement is approved, set a password out of band, grant `LOGIN`, point `DATABASE_URL` at `sioona_runtime`, and point `MIGRATION_DATABASE_URL` at the owner. Cross-tenant recovery must use the owner URL.
4. Record role attributes and counts only. Do not record the password or transcripts.

## Residual scope

Workspaces, memberships, uploads, pilot settings, taxonomy, pilot requests, and inference control/budget/reservation tables have no RLS policy. That matches the card's table list. Application tenant filters and CB-03 cover them until a later card extends policies. This is not a deferral of CB-04.
