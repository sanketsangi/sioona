## What landed

Migration `024_tenant_rls` creates `sioona_runtime` as `NOLOGIN`, `NOSUPERUSER`, and `NOBYPASSRLS`. It enables and forces row level security, one table at a time, on `messages`, `conversations`, `signal_predictions`, `signal_feedback`, `supervised_action_decisions`, `detection_runs`, `inference_attempts`, and `signal_evidence`. The policy is `tenant_id = current_setting('app.tenant_id', true)` for both reads and writes. Missing context matches nothing.

API requests bind that setting after the tenant is known and before tenant queries. The setting is transaction-local, and request teardown clears the context variable. Alembic uses `MIGRATION_DATABASE_URL` when it is set, otherwise `DATABASE_URL`. The runtime role is not given a password in this revision.

Downgrade drops each policy and disables RLS. It keeps the role so an operator password would survive a policy rollback.
