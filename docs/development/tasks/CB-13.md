## Goal and Invariants

Choose models by quality-adjusted cost per actionable signal, not by cheapest token. Enforce controlled promotion gates so that no candidate model or route is promoted without passing an unchanged D5 holdout comparison against an approved baseline digest.

- Humans approve consequential actions; nothing auto-sends.
- Quality-adjusted cost penalizes false positives and ungrounded evidence:
  `cost_per_conversation = total_cost / total_evaluated`
  `quality_adjusted_cost = total_cost / effective_true_positives`
- Live holdout calls remain blocked until an approved external corpus meets D5 ($n \ge 120$, $\ge 30$ per class).
- Offline preflight verifies sample feasibility without spending provider calls or touching private paths.
- All evaluation in this milestone runs offline using synthetic items and recorded replays (zero provider calls).

## Implementation Summary

1. **Holdout feasibility preflight and baseline-digest gate** (`web/eval/gate/holdout.ts`, `HOLDOUT.md`, `web/package.json`):
   - Added `eval:holdout:preflight` script.
   - `assertHoldoutFeasible`: rejects the frozen 100-item holdout before corpus reads or network calls (`holdout_sample_size`).
   - `assertHoldoutItems`: checks class balance (≥ 30 items per class) and customer turn presence.
   - `ApprovedBaseline` contract: requires `EVAL_HOLDOUT_BASELINE_APPROVAL` JSON with baseline identity and SHA-256 digest (`holdoutResultDigest`).
   - `comparePromotion`: fails closed with `baseline_unapproved` or `baseline_mismatch` if the baseline differs from the approved operator digest.
   - Preserves reviewed language (`en`, `hi`, `hinglish`), tags, and injection attack metadata.

2. **Staged routing pipeline as code** (`web/src/lib/ai/router.ts`):
   - `StagedRouteDefinition`: defines `route_version`, `screenStage`, `detectStage`, `verifyStage`.
   - `evaluateScreenStage`: fast heuristic pre-filter validating minimum customer turn characters and non-empty customer input. Screens out unactionable conversations before model invocation (recall includes screened-out items at 0 cost).
   - `evaluateVerifyEscalation`: escalation rules triggering the stronger verifier on borderline confidence ($0.55 \le \text{confidence} < 0.82$), critical signal types (`retention`), ambiguous multi-turn quotes, or daily-quota primary fallbacks.
   - `executeStagedRoute`: executes the staged pipeline with `InferenceAttempt` auditing across each executed stage (`screen`, `detect`, `verify`).
   - `MODEL_PRICING_TABLE`: verified rates as of 2026-10-14 for `qwen/qwen3.8-27b` ($0.20/$0.10/$0.40), `openai/gpt-oss-20b` ($0.15/$0.075/$0.30), `deepseek/deepseek-r1-distill-qwen-14b` ($0.10/$0.05/$0.20), and `meta/llama-3.3-70b-versatile` ($0.59/$0.30/$0.79). Source: https://groq.com/pricing.
   - `computeQualityAdjustedBenchmark`: calculates cost per conversation, raw cost per signal, quality-adjusted cost per actionable signal, and quality efficiency index.
   - `compareRouteBenchmarks`: evaluates candidate vs baseline routes against D5 thresholds, blocking candidates that increase quality-adjusted cost or degrade quality/recall.

3. **Scanner exemption for synthetic test idempotency keys** (`.gitleaks.toml`, `web/e2e/scan-gate.test.mjs`):
   - Added strict AND-condition allowlist for `backend/tests/test_pilot_requests.py` covering synthetic test idempotency keys (`^global-pilot-test-000[123]$`) committed to history in `9258e06`.

## Adversarial Code Review Sign-off (2026-10-14 — Round 2)

Second-round independent adversarial audit and edge-case hardening on `cb/CB-13-routing-benchmark`:

1. **Unmeasured Evidence Validity Accounting (`router.ts`)**:
   - Fixed `computeQualityAdjustedBenchmark` where `validActionableSignals` used `input.evidenceValidityRate ?? 0`, which caused an unmeasured cohort (`evidenceValidityRate: null`) to report 0 valid actionable signals despite having 54 effective true positives. Replaced with `Math.round(surfaced * evidenceMultiplier)` so unmeasured cohorts consistently evaluate to `surfaced` valid signals, matching `effectiveTP`.
2. **Division by Zero Protection in Route Deltas (`router.ts`)**:
   - Added epsilon clamping `Math.max(1e-6, ...)` to `deltaQualityAdjustedCostPct` and `deltaEfficiencyPct` in `compareRouteBenchmarks` so a zero baseline cost or zero efficiency index cannot evaluate to `Infinity` or `NaN`.
3. **Strict Zero Effective True Positive Rejection (`router.ts`)**:
   - Hardened `compareRouteBenchmarks` so candidate routes with 0 effective true positives or `null` quality-adjusted cost are strictly blocked even if the baseline also had zero signals.
4. **Defensive Input Guards (`router.ts`)**:
   - `calculateAttemptCostUsd`: Clamped `cachedInputTokens` to `usage.inputTokens` so anomalous provider usage reporting cannot exceed total input tokens.
   - `evaluateScreenStage`: Safely filtered customer message inputs with `typeof m === "string"` before trimming.
   - `evaluateVerifyEscalation`: Used optional chaining `(classification.quotes?.length ?? 0)` to guard against omitted/undefined quotes.
   - `executeStagedRoute`: Bounded attempt latency to non-negative values (`Math.max(0, latencyMs)`).

## Adversarial Code Review Sign-off (2026-10-14 — Round 3)

Third-round independent adversarial audit, defect fixes, and robustness hardening on `cb/CB-13-routing-benchmark`:

1. **Undefined Evidence Validity Multiplier Bug (`router.ts`)**:
   - `input.evidenceValidityRate !== null ? input.evidenceValidityRate : 1` evaluated to `undefined` when `evidenceValidityRate` was omitted or passed as `undefined` (since `undefined !== null` is true). Multiplying by `undefined` resulted in `validActionableSignals: NaN`, `effectiveTruePositives: NaN`, and `qualityEfficiencyIndex: NaN`.
   - Replaced with `typeof input.evidenceValidityRate === "number" && Number.isFinite(input.evidenceValidityRate) ? Math.max(0, Math.min(1, input.evidenceValidityRate)) : 1`, guaranteeing finite bounds $[0, 1]$ and clean default `1.0`.
2. **False Falsy Trap in Delta Efficiency Calculations (`router.ts`)**:
   - `compareRouteBenchmarks` condition `if (baseline.qualityEfficiencyIndex && candidate.qualityEfficiencyIndex)` checked truthiness. When candidate efficiency dropped to 0, `0` was falsy, causing the delta to be skipped and reported as `null` instead of `-100%`.
   - Updated to check `baseline.qualityEfficiencyIndex !== null && candidate.qualityEfficiencyIndex !== null`, ensuring full drops to zero efficiency report `-100%`.
3. **Subprocess RangeError Vulnerability on Latency (`router.ts`)**:
   - In `recordAttempt`, `boundedLatencyMs` did not check `Number.isFinite(latencyMs)`. If an invoker returned `NaN`, `new Date(Date.now() - NaN).toISOString()` threw an uncaught `RangeError: Invalid time value`. Additionally, the stored attempt's `latencyMs` had assigned the unbounded argument rather than the bounded value.
   - Updated to `Number.isFinite(latencyMs) ? Math.max(0, latencyMs) : 0` and stored `boundedLatencyMs`.
4. **Token Cost Bounds & Non-Finite Guards (`router.ts`)**:
   - Guarded `calculateAttemptCostUsd` against negative and non-finite token counts (`inputTokens < 0`, `outputTokens < 0`, `!Number.isFinite(...)`), returning `null` instead of calculating negative or `NaN` dollar costs. Defaulted `cachedInputTokens` to 0 when `NaN`.
5. **Defensive Input Guards on Customer Message Arrays (`router.ts`)**:
   - Added `Array.isArray` guards and string content checks across `evaluateScreenStage` and `executeStagedRoute` to prevent unhandled `TypeError` crashes on missing properties or non-string turns.
6. **Parallel Test Flake Protection (`run-gate.test.ts`)**:
   - Added a 15,000ms timeout to `eval:gate replay > emits and saves the full artifact from the CLI` to prevent timeouts when spawned under heavy parallel worker contention.
