## Implementation and ownership

- `027_jobs` follows `026_weekly_upload_receipts`. Composite identity is
  `(tenant_id, id)`; `upload_id` has a tenant-bound foreign key. Jobs store only
  bounded references: upload ID, conversation identity/content digest, count,
  integer cursor and `config_sha256`. No transcript, provider response, key or
  arbitrary JSON payload is stored on the queue row. Priority, attempts (maximum
  three), schedule, fencing token, owner, lease/heartbeat times, error category
  and timestamps have explicit constraints/indexes.
- Canonical conversations/messages, the immutable source snapshot in the existing
  `uploads` store, and the outbox row commit together. A worker cannot observe a
  job before that commit. Same upload identity replays return the existing job;
  conflicting source data and overlapping live jobs reject without partial
  writes. Detect snapshots preserve canonical external IDs and ground truth.
- The `jobs` table enables **FORCE RLS**, the D8 `tenant_isolation` policy, and
  runtime CRUD grants. Enqueue/status/cancel always verify an actor or allowed
  principal, even when legacy auth is off/shadow. Tenant identity never comes
  from an unverified job body. All worker reads/writes filter the tenant and bind
  transaction-local RLS scope.
- `python -m app.worker` uses the API's backend revision and runtime URL, never
  `MIGRATION_DATABASE_URL`. Startup requires Postgres, current role exactly
  `sioona_runtime` with no superuser/BYPASSRLS, and enabled/forced jobs RLS. The
  operator's explicit `SIOONA_WORKER_TENANTS` allowlist is the local authority for
  `principal:detection-worker`; it does not enumerate tenants through an owner
  connection. The principal has narrow metering/detection/read permissions and
  cannot enqueue/cancel as an API client.
- Claims use `FOR UPDATE SKIP LOCKED`, priority/creation ordering, a 90s lease and
  monotonically increasing `lease_token`. An independent session renews every
  30s. Admission, publication and completion lock the job and check owner/token,
  status and wall-clock expiration **after** acquiring locks; admission rechecks
  after budget locking. Claims/heartbeats hold no provider I/O transaction.
- Retry failures preserve unpublished or changed conversation IDs in
  `detection_resume`; `run_after` uses bounded exponential backoff. At three
  attempts jobs become `dead_lettered`, including a third-attempt worker crash.
  Cancellation fences a call already in flight and leaves resume information.
  Pause stops claims and releases partial leases to queued without consuming a
  failure attempt. SIGTERM stops claims and lets the current call drain.
- Before **each** provider call, including quota fallback, the worker commits a
  CB-07 reservation and separate CB-06 `pending` attempt. A reclaimed worker
  creates a new admission; ambiguous admissions are never refunded/reused.
  Missing usage remains `NULL` with `usage_status='unknown'`. Ledger finalization
  belongs to the individual attempt and remains possible after job cancellation;
  signal publication still requires the active lease fence.
- Publication remains in `reconcile_detection`, keyed by tenant/job/conversation
  with immutable content hash checks. Signals, CB-08 evidence and cursor commit
  together; unchanged completed conversations are skipped after restart, before
  another provider call. A changed conversation fails closed and remains in
  resume. Final completion publishes upload/per-file membership and the weekly
  receipt/pilot increment atomically. Upload snapshots reconstruct from canonical
  source plus committed detection history; no runtime store JSON is required.
- Inline publication into an active durable identity is refused even across a
  flag rollback. The old recovery cron permanently excludes uploads that have
  jobs, so it cannot become a competing processor.

## Processor flag and API contract

`SIOONA_DETECTION_EXECUTION=inline|worker` defaults to **inline** in both packages.
Web worker mode requires canonical `SIOONA_STATE_MODE=postgres`; invalid flags
fail closed. Keep both processes on matching mode/revision at cutover.

| Request | Worker behavior |
| --- | --- |
| Web `POST /api/ingest` | Keeps parsing, tenant authorization and upload confirmation guards; returns HTTP 202 with durable job status without inline detection or a client-computed weekly increment. |
| Web `POST /api/detect` | Enqueues canonical conversation references and returns HTTP 202. |
| Adapt redetect / live ingestion | Queues work and returns the job alongside the accepted result. |
| Web `GET /api/jobs/{jobId}` | Authenticated, tenant-scoped status proxy for polling. |
| API `PUT /v1/tenants/{tenant_id}/jobs/uploads/{upload_id}` | Verified canonical ingestion/outbox transaction; HTTP 202. |
| API `POST /v1/tenants/{tenant_id}/jobs/detect` | Bounded conversation IDs and idempotent `request_id`; HTTP 202. |
| API `GET /v1/tenants/{tenant_id}/jobs/{job_id}` | Bounded status/counts/schedule/error response; no source text or secrets. |
| API `POST /v1/tenants/{tenant_id}/jobs/{job_id}/cancel` | Verified reviewer cancellation and fencing. |

Both the production ledger wrapper and Next's Groq provider boundary reject
inline calls in worker mode, including calls made from `after()`. Existing
inline behavior is retained by default. Requests with changed source/config use
a new reviewed request identity after investigation; do not edit immutable
snapshots or manually reset attempts/counters to force a retry.

## Gateway port and unchanged semantics

`backend/app/ai/gateway.py` is the sole Python provider I/O boundary. It ports the
existing v3 prompt, redaction/pseudonyms, complete recent-turn context, Groq
request shape, response parsing, instruction/evidence grounding, heuristics,
urgency and commercial values. Provider errors are bounded categories, never
raw response bodies in logs/ledger. Job config identity includes the gateway
implementation, prompt, model/fallback settings, base rules and active tenant
overrides; revision/config drift fails closed.

The prompt copies at `web/eval/promptfoo/system-prompt.txt` and
`backend/app/ai/system-prompt.txt` are checksum-tested against the existing web
`SYSTEM_PROMPT`. A fixture/source checksum suite ties the port to the original
120-item CB-09 validation corpus and captures. To regenerate from **reviewed**
web sources/replays, without provider calls, run from the repository root:

```bash
web/node_modules/.bin/tsx web/scripts/export-python-gateway.ts
(cd backend && python -m pytest tests/test_gateway.py -q)
```

Do not regenerate checksums to conceal a model/prompt/rule change; such a change
still needs an eval comparison. Gateway routing, v3 prompts, CB-08 code-point
anchors and human keep-set `SignalScore >= 80%` (`n >= 5`) remain unchanged.
Nothing auto-sends; Approve is decision-only and Acted remains display-only.

Postgres proofs use independent runtime-role transactions, not SQLite simulations:

- Two simultaneous claimers finish their claim while the first lock is still
  held; exactly one claims the only job (`SKIP LOCKED`).
- Expired leases are reclaimed with a larger token. Stale heartbeat,
  publication and completion fail; the new owner alone publishes/completes.
- Publication rolled back before commit is retried; publication committed before
  crash is skipped. Simulated process loss before dispatch, after response,
  before publication and after publication keeps every admission metered and
  produces exactly one committed detection run.
- Cancellation during a provider call records the attempt but prevents signal
  publication and preserves resume IDs. Missing tokens remain unknown/NULL.
- Three abandoned leases dead-letter; cross-tenant reads/updates return no rows,
  cross-tenant inserts fail RLS, missing scope sees zero, and schema constraints
  reject invalid states/attempt ceilings/cursors. The RLS suite now covers eleven
  tables, including jobs.
- The executable refuses the owner connection. Unit checks additionally cover
  pause drain, budget denial without dispatch, quota fallback admissions,
  immutable upload identity, detect metadata preservation, snapshot rebuilding,
  changed-source resume and recovery-cron exclusion after rollback.

The test suite establishes code boundaries, not hosted process/restart or
observation acceptance. The Draft PR's exact-head CI results remain separate
receipts; an earlier local check is not proof of a later head's CI success.
