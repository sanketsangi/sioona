## Implementation

- Canonical conversations/messages, immutable upload source and reference-only
  jobs outbox commit together. Enqueue helpers never commit; verified API routes
  own that transaction. Replay returns the existing job; conflicting source or
  overlapping active corpus rejects without partial writes.
- FastAPI exposes verified tenant-scoped upload/detect enqueue, status and cancel
  APIs. Web upload/detect/live routes enqueue in worker mode; Adapt returns the
  queued job. `/api/jobs/{jobId}` polls using the authenticated server tenant.
  New job APIs require verified actor/principal authority even in off/shadow
  auth modes. Job status contains bounded counts/categories, never source text.
- `Worker.tick` rotates the starting tenant each iteration, including empty
  tenants. The actual executable uses this method, so continuous work for the
  first configured tenant cannot starve later tenants. Trusted assignments come
  from `SIOONA_WORKER_TENANTS`, never request/job values.
- Claims use tenant-filtered `FOR UPDATE SKIP LOCKED`, 90-second leases,
  30-second heartbeat, monotonic fencing tokens, at most three attempts,
  exponential backoff, cancellation and dead letters. Provider I/O runs outside
  database transactions. The executable verifies Postgres, exact non-bypass
  runtime role and enabled/forced jobs RLS before processing.
- Each provider attempt, including fallback, commits a CB-07 reservation and
  separate CB-06 pending ledger row under `principal:detection-worker` before
  dispatch. Unknown usage stays NULL; ambiguous admissions are never refunded
  or reused. Ledger finalization survives cancellation/lease loss.
- Publication uses `reconcile_detection` with tenant/job/conversation identity
  and immutable source/config hashes. Lease ownership/token/status/expiration
  are checked under locks before publication and before commit. Evidence,
  detection output and cursor commit atomically. Already committed conversations
  are skipped before another provider call on restart.
- Failure/cancellation preserve unpublished or changed IDs in `detection_resume`.
  Pause drains preserve only unpublished IDs as skipped without consuming a
  retry; successful completion clears the processed IDs. Completion publishes
  upload membership, weekly receipt and pilot increment atomically. Parent and
  per-file snapshots reconstruct from persisted source and detection history.
- `SIOONA_DETECTION_EXECUTION=inline|worker` defaults to inline. Worker web mode
  requires canonical Postgres. Upload/detect/Adapt/live paths avoid inline
  classification; both the ledger wrapper and Groq transport reject inline calls
  in worker mode, including deferred callbacks. Canonical inline publication
  refuses active durable identities even during rollback; the old recovery cron
  excludes durable jobs permanently.
- The Python gateway ports the existing v3 prompt, recent-turn context,
  redaction, parser, evidence grounding, heuristics, urgency and commercial
  values. Prompt copies and original source hashes are checksum-tested. All 120
  existing CB-09 replay fixtures prove request/parser/output parity. Models,
  prompt, thresholds and human keep-set SignalScore ≥80% (n ≥5) are unchanged.
