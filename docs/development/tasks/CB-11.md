# CB-11 — Durable jobs runtime

Local implementation authorized by Sanket on 2026-10-14, superseding the older
implementation gate for this branch only. Hosted CB-10 acceptance is still open.
No hosted change, provider spend, PR #162 action, or marketing-site edit is authorized.

## This slice

- Prepared `027_jobs` after `026_weekly_upload_receipts`; not applied. Source
  revision chain was inspected without running Alembic.
- Reference-only tenant jobs, deduplicated by tenant/kind/upload/config/corpus
  digest. `enqueue` never commits: the caller must insert the outbox row in the
  canonical ingestion transaction. No new enqueue HTTP endpoint is exposed.
- Tenant-filtered `FOR UPDATE SKIP LOCKED` claims, 90-second leases, monotonic
  fencing tokens, 30-second heartbeats, exponential retry backoff, three attempts,
  cancellation and dead letters. Recovery handles expired leases in batches of 100.
- Fenced publication callback and success state share one transaction and row
  lock. Callbacks must use the supplied session and must never commit themselves.
  Provider calls belong outside that transaction.
- `Worker` runs an injected handler, renews leases while it works, stops new
  claims on pause/stop, drains the current job, and records category-only failures.
  Worker tenant assignments must come from trusted server/operator configuration.
  It binds transaction-local tenant context and never uses an owner/migration URL.
- `python -m app.worker` defaults to `SIOONA_DETECTION_EXECUTION=inline` and exits
  without opening a database. `SIOONA_WORKER_PAUSE=1` also exits cleanly. CLI worker
  mode returns exit code 2 until a metered detection handler is wired; it cannot
  accidentally run alongside the existing inline detection path.

## Validation without Alembic

Jobs tests require `CB11_TEST_DATABASE_URL` pointing at loopback database
`sioona_cb11_test`. They directly create/drop the ORM jobs table on disposable
Postgres and install a test-only non-bypass role/policy for RLS checks. They never
call Alembic or providers. Standard Postgres migration tests have been extended
for the new head and jobs tenant isolation; running those requires separate
permission to run Alembic and was excluded from this session.
