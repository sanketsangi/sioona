### P0 — Dependabot and secret scanning absent

Failure: `.github/dependabot.yml` was missing, and the workflow had no secret-scanning job.

Failing test first: `web/e2e/scan-gate.test.mjs` failed on the missing Dependabot file, the missing `gitleaks` job, and the missing canary. After those files existed, gitleaks 8.28.0 did not flag `AKIAIOSFODNN7EXAMPLE` (the default `aws-access-token` rule allowlists values ending in `EXAMPLE` and only matches `[A-Z2-7]`). The fixture was changed to the synthetic value `AKIA234567BCDEFGHIJK`, which that rule flags. It is not a credential.

Resolution: added the cookbook Dependabot scaffold (weekly npm `/web`, npm `/site`, pip `/backend`, github-actions `/`). Added a `Gitleaks` job that copies the canary to a temp directory and requires gitleaks 8.28.0 exit code 1, then scans history with `gitleaks/gitleaks-action@e0c47f4f8be36e29cdc102c57e68cb5cbf0e8d1e` (`v3.0.0`), `pull-requests: read`, and `GITLEAKS_ENABLE_COMMENTS: false`. `.gitleaks.toml` allowlists `.github/secret-scan-fixture/` so the committed canary does not fail the repository scan. GitHub secret scanning was not enabled. `GET /repos/sanketsangi/sioona/secret-scanning/alerts` returned 404: "Secret scanning is disabled on this repository."

Evidence (2026-10-07):

- `GITLEAKS_BIN` gitleaks 8.28.0, `node --test e2e/scan-gate.test.mjs e2e/ci-gate.test.mjs` → 5 passed, 0 failed. The canary step exits 1.
- The same canary under `.github/secret-scan-fixture/` with `.gitleaks.toml` → exit 0, no leaks.
