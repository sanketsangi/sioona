The admin-only `GET /v1/tenants/{tenant_id}/economics-dashboard` endpoint uses a half-open UTC window (`from <= timestamp < to`), defaults to the trailing 30 days, and caps the requested window at 366 days. The route always requires a verified `X-Sioona-Actor` JWT and a current, unrevoked admin membership for the path tenant, including when the general actor-auth mode is `off` or `shadow`. Every canonical-table select has an explicit `tenant_id` predicate and remains compatible with the existing runtime RLS context.

Only metric-bearing columns are selected. Detection output, signal summaries/evidence text, feedback notes, job error text, messages, and transcripts are neither loaded nor returned.

## Metric contract

The response declares `Asia/Kolkata`, `USD`, and `INR`. Funnel counts include a typed denominator map and these timestamp bases:

| Metric | Definition / timestamp basis | Denominator |
| --- | --- | --- |
| Ingested | Sum of upload-job `conversation_count` by job `created_at` | none |
| Processed | Distinct conversations with completed detection runs by run `created_at` | ingested |
| Surfaced | Active predictions by prediction `created_at` | processed |
| Reviewed | Feedback by `reviewed_at`, joined to its tenant prediction regardless of prediction `created_at` or active state | surfaced |
| Correct | Canonical `correct` feedback | reviewed |
| Acted | Surfaced predictions marked acted | surfaced |
| Positive outcomes | Surfaced retained or converted outcomes | acted |
| Influenced INR | Recorded value on positive outcomes; not incremental revenue | positive outcomes |

Quality reports the arbitrary-window human acceptance rate (`correct / reviewed`, with partial and incorrect retained in the denominator), feedback counts, type acceptance, false positives, evidence validity/failure, and abstention (completed runs without any persisted prediction, including superseded predictions). Gold-set precision, recall, and calibration are typed `unavailable` because the approved tables do not contain gold labels or calibration buckets.

Reliability reports windowed job and attempt outcomes, retries/recoveries, 429s, errors, interpolated p50/p95 provider latency, and p50/p95 durable job processing latency (`updated_at - created_at` for terminal jobs). Current queued/leased depth and age plus pending inference attempts are queried independently of the reporting window. Ledger-flush failures, reservation drift, database latency, and connector telemetry remain typed `unavailable` with reasons.

Economics excludes unknown usage/cost from token and cost arithmetic. It separately reports unknown counts/rates and known-cost coverage. Window totals split known cost into estimated and reconciled USD. Unit costs and the 10K/50K/100K projections use only `screen`, `detect`, and `verify` attempts attributed to the window's completed detection-run cohort, including later-reconciled receipts; report/action-draft spend and attempts for other or unfinished runs cannot enter the cohort numerator. All four unit costs and projections are unavailable when that cohort has no known-cost attempt. Projections divide the unrounded cohort cost by distinct processed conversations before rounding the final result.

## Independent review resolutions

- P1 actor authorization: the dashboard route is in the always-enforced route set, so legacy tenant/role headers cannot authorize it in `off` or `shadow`; the web caller always mints the verified actor assertion.
- P2 review window: acceptance joins feedback selected solely by half-open `signal_feedback.reviewed_at` to the matching tenant prediction, including old and superseded predictions.
- P2 cohort economics: unit-cost and projection numerators are restricted to detection-stage attempts attached to completed runs in the requested cohort; unknown-only cohorts return `Unavailable` for all four unit costs.
- P2 live reliability: active queue depth/age and pending-attempt age ignore the historical window; processing latency uses persisted terminal job timestamps and is reported separately from provider latency.
- P2 spend anomaly: each IST day's denominator is the set of distinct processed conversation IDs, not the number of detection runs.
- P2 UI semantics: the arbitrary-window card is labeled `Human acceptance rate`; the pilot-only `SignalScore` name is not shown on this dashboard.
- Cookbook reconciliation: the Postgres runtime-role test executes all four §13.3 SQL blocks and reconciles their run, daily economics, acceptance, and funnel outputs with the dashboard contract.

## Alerts and runbooks

| Alert | Threshold | Owner / runbook |
| --- | --- | --- |
| Unknown usage/cost | any attempt | AI Platform — reconcile provider receipts and preserve NULL unknowns |
| Unfinished attempt | pending over 15 minutes | Backend — inspect ledger rows before retrying |
| Queue age | queued/leased over 15 minutes | Worker — inspect workers, leases, and tenant rotation |
| Dead letters | any dead-lettered job | Worker — fix the bounded error cause before resume |
| Provider throttling | any HTTP 429 in-window | AI Platform — reduce concurrency and verify `Retry-After` |
| Invalid evidence | any stale/unresolved active prediction | Trust — quarantine and reconstruct from persisted source |
| Spend anomaly | latest populated IST day exceeds 2× the median of at least three preceding populated days | AI Economics — compare route, retries, cache, and unit cost |

Unsupported cookbook alerts (ledger flush, reservation drift, database latency, connectors) are rendered `unavailable`, each with an owner, reason, and runbook line.
