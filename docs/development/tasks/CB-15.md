The admin-only `GET /v1/tenants/{tenant_id}/economics-dashboard` endpoint uses a half-open UTC window (`from <= timestamp < to`), defaults to the trailing 30 days, and caps the requested window at 366 days. The actor guard verifies an admin membership for the path tenant. Every one of the five canonical-table selects has an explicit `tenant_id` predicate and remains compatible with the existing runtime RLS context.

Only metric-bearing columns are selected. Detection output, signal summaries/evidence text, feedback notes, job error text, messages, and transcripts are neither loaded nor returned.

## Metric contract

The response declares `Asia/Kolkata`, `USD`, and `INR`. Funnel counts include a typed denominator map and these timestamp bases:

| Metric | Definition / timestamp basis | Denominator |
| --- | --- | --- |
| Ingested | Sum of upload-job `conversation_count` by job `created_at` | none |
| Processed | Distinct conversations with completed detection runs by run `created_at` | ingested |
| Surfaced | Active predictions by prediction `created_at` | processed |
| Reviewed | Feedback by `reviewed_at`, joined to surfaced predictions | surfaced |
| Correct | Canonical `correct` feedback | reviewed |
| Acted | Surfaced predictions marked acted | surfaced |
| Positive outcomes | Surfaced retained or converted outcomes | acted |
| Influenced INR | Recorded value on positive outcomes; not incremental revenue | positive outcomes |

Quality reports SignalScore (`correct / reviewed`, with partial and incorrect retained in the denominator), feedback counts, type acceptance, false positives, evidence validity/failure, and abstention. Gold-set precision, recall, and calibration are typed `unavailable` because the approved tables do not contain gold labels or calibration buckets.

Reliability reports job and attempt outcomes, retries/recoveries, queue depth/age, 429s, unfinished attempts, errors, and interpolated p50/p95 provider latency. Ledger-flush failures, reservation drift, database latency, and connector telemetry remain typed `unavailable` with reasons.

Economics excludes unknown usage/cost from token and cost arithmetic. It separately reports unknown counts/rates and known-cost coverage. Known cost is split into estimated and reconciled USD; unit costs use processed conversations and surfaced/correct/acted signals. The 10K/50K/100K projections multiply measured known cost per processed conversation. Zero processed conversations make projections unavailable; any unknown cost marks them incomplete.

## Alerts and runbooks

| Alert | Threshold | Owner / runbook |
| --- | --- | --- |
| Unknown usage/cost | any attempt | AI Platform — reconcile provider receipts and preserve NULL unknowns |
| Unfinished attempt | pending over 15 minutes | Backend — inspect ledger rows before retrying |
| Queue age | queued/leased over 15 minutes | Worker — inspect workers, leases, and tenant rotation |
| Dead letters | any dead-lettered job | Worker — fix the bounded error cause before resume |
| Provider throttling | any HTTP 429 in-window | AI Platform — reduce concurrency and verify `Retry-After` |
| Invalid evidence | any stale/unresolved active prediction | Trust — quarantine and reconstruct from persisted source |
| Spend anomaly | latest populated IST day exceeds 2× the median of at least three preceding populated days | AI Economics — compare route, retries, cache, and unit cost |

Unsupported cookbook alerts (ledger flush, reservation drift, database latency, connectors) are rendered `unavailable`, each with an owner, reason, and runbook line.
