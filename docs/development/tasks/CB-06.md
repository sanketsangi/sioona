## Behavior

- `POST /v1/tenants/{tenant_id}/inference-attempts` accepts up to 500 rows, is idempotent on `(tenant_id, attempt_id)`, rejects a cross-tenant row for the whole batch, and rejects turning a finalized row back into `pending`.
- Usage `unknown` stores null tokens, never zero. Cost is `unknown` while `RATES` is empty.
- `GET …/inference-usage` and `GET …/detection-runs/{run_id}/inference` return aggregates only.
- Web buffers one sink per run, stamps the publication run id when `syncDetectionRun` or `publishAtomicIngest` computes it, and flushes in `finally` with three tries. A failed flush logs `sioona.inference_ledger.flush_failed count=N` only.
- Ledger preflight failure sets `skipLlm` and `ledgerSkip=unreachable`. Heuristics still publish. No provider call runs.
- D2 crash window: a process death between the provider response and a successful flush drops those rows. CB-11 closes that by writing `pending` before the call. CB-15 owns alerting beyond the counts-only log.
- Deploy note: a web deploy that can see `DETECT_LLM=1` before this API is live will skip the LLM until the ledger GET succeeds. Hosted Neon already has the table; the routes ship with this card.

## Review follow-ups (2026-10-08)

- Flush chunks at ≤500 (`LEDGER_FLUSH_CHUNK`) so a large primary run cannot 422 the batch max.
- Run-scoped GET uses `RUN_ROLLUP_SQL` / `run_usage_groups` (provider, model, stage) and stamps `detection_run_id` on each group.
- Tenant `inference-usage` without `from`/`to` defaults to the last 30 days (IST-aware day grouping unchanged).
- Finalized rows are first-write-wins: a later flush returns `replayed` and does not rewrite tokens/status.
- Showcase / hydrate / load-testing paths may flush attempts with null `detection_run_id` when they never publish a detection run. Run rollups exclude those rows by design until a publication stamps an id.
- GET-only preflight remains: a write failure after LLM spend is still the D2/CB-15 alert gap (`flush_failed` count log only).
